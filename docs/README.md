## 阅读路径

**第一次接触这个仓库（人）**

1. 根目录 [README](../README.md) 的「快速开始」，先把服务跑起来；
2. [01 架构](01-architecture.md)，建立「实例是容器」的心智模型；
3. [03 数据模型](03-data-model.md)，知道数据落在哪；
4. 按任务读：改页面看 08，改接口看 02 + 07，动实例看 05，动内核看 06。

**部署 / 运维**

1. [09 部署](09-deployment.md) 的「单容器」与「升级 / 备份」；
2. [05 运行时](05-browser-runtime.md) 的端口、卷与排障；
3. [04 认证](04-auth-rbac.md) 的生产检查清单。

**AI / 自动化代理**

1. 先读 [11 AI 操作手册](11-ai-guide.md)，尤其是「不变量」与「验证矩阵」；
2. 再按任务读对应模块文档；
3. 动手前先确认当前工作区状态（`git status`、容器状态、目标页面是否已定版）。

## 文档约定

- **代码是唯一真相**。文档写设计意图、边界与坑；字段清单、接口路径这类容易漂移的内容，
  以代码 / `/docs` / `alembic` 为准，发现不一致先改文档再改代码。
- 路径、命令、环境变量一律用仓库内真实值，不写「示例域名」这类无法执行的东西。
- 每个模块文档都包含：职责、关键文件、数据流、扩展方式、常见故障。
- 变更代码时，同一个 PR 内更新受影响的文档；新增模块时补一篇并在本页登记。
